# 第 5 次课 · 教硬件学会看（学员文档）

_柴火创客学园 M0 · 零基础智能硬件入门_

## 一、这节课你会带走什么

上节课你指挥 AI 团队做出了番茄钟。今天，你的硬件要学一个全新本事：**看**。不给它写一句指令——你给它看照片，它自己学会认。

下课的时候，你会有四样东西：

1. **一个自训练的视觉模型**——亲手采集、训练、部署到板子，能认出你自己的剪刀、石头、布；
2. **一条归因记录**——"我的模型在什么情况下认错"，写在日志里，越具体越好；
3. **一张三格单（视觉联动版）**——感知、逻辑、输出，逻辑格里多一栏"认不出时怎么办"；
4. **一个跑通的视觉联动作品**——认出 ≥1 种手势，就触发 ≥1 个动作（灯亮、铃响）。

先说清楚这节课的玩法：**老师引导＋这份文档＋AI 对话 → 你自己的作品和记录。**每一步老师让你写的东西，都记在这份文档上（用电脑就记在 md 文档里，手写就写在纸上）——下课要交，下次课第一件事就要用你的模型。

## 三、认识新装备：XIAO ESP32S3 Sense

你的第三块板子。第一块 Grove 套件是**皮肤**（感觉冷热动静），第二块 Wio 是**脸**（有屏幕有按键），这块拇指大的小板子是**眼睛**——带摄像头，还自带麦克风，能看也能听。

| 特性 | 说明 |
| --- | --- |
| 大小 | 拇指大（21×17.5mm） |
| 摄像头 | OV2640，200 万像素 |
| 麦克风 | 数字麦克风，可录音 |
| 存储 | microSD 卡槽 |
| 无线 | WiFi ＋ 蓝牙 |
| AI 能力 | AI 模型直接跑在板子上，**不用联网** |

课上老师在解剖图上带你认了一圈。不用全背，只要认得三样：**摄像头**（它的眼睛）、**复位键**、**启动键**（烧录程序要用）。

**优点三条**：小——哪都能塞；便宜——一顿午饭钱；AI 在板子上跑——不用联网，你的照片不出这块板子。

**缺点三条**（今天全会撞上）：算力小——它"想事情"慢半秒，正常；会认错——所以"认不出时怎么办"是你设计的一部分；没有屏幕——靠灯、靠铃、或连到电脑上看。

记住一句：**小电脑办小事**——让它看完管好你这一件事，就是它最合适的活。

## 四、体验一：AI 的 Blink——先用别人教好的

今天的武器库：**sensecraft.seeed.cc/ai**（SenseCraft AI，教板子认东西的地方）。

第一步不拍照、不训练——先把一个**别人教好的模型**装进你的板子，看看"认出来"长什么样：

1. USB-C 线连接 XIAO 到电脑（线两头都插到底）；
2. 打开 SenseCraft，点"连接设备"，看到你的板子名字；
3. 选一个预训练模型（人脸检测），点"部署"，等待烧录完成；
4. 配置"触发"：**认出人脸 → 点亮板上的 LED**；
5. 对准目标验证——亮了！

**成功标志**：认出目标，LED 亮。认出它的不是你家的网，也不是远方的服务器——**是你手里这块板子自己**。拔了线、断了网，它照样认。

> 老师还演示了进阶版：装上 Grove 扩展板接一根灯带——认出目标，灯带直接亮。**不用写一行代码**，视觉模型直接驱动外设。这就是今天的命题预告：认出它 → 让它动起来。

别人教的经验册，好用——**但它不认识你**。下一步，教一个你自己的。

**写在这里：**

- □ 我的板子连上了，现成模型部署成功，认出目标 LED 亮了

## 五、体验二：教它认你的手势

现在，教它认你的手势：剪刀、石头、布。

### 第 1 步：建站（老师带你点）

选开发板（XIAO ESP32S3 Sense）→ 选串口 → 给三个类别起名字。**类别名用英文**：`scissors`、`rock`、`paper`（屏幕显示不赌中文）。

### 第 2 步：采集——每一类，拍 25 到 30 张

- 变着花样拍：手放正一张、远一点一张、换个角度一张、换只手一张；
- 每张照片选好"答案名"——它学习就是在对答案。"答案名"的正式说法叫**标签**：每张照片的标准答案。

> ⛔ **规矩：只拍手，不拍脸**——你的、别人的都不行。拍到人脸，当场删掉。

### 第 3 步：训练＋部署

点"训练"——它在把你的一百多张照片变成"经验"：石头有什么共同点、剪刀有什么共同点，自己总结，存成一本"经验册"。训练好，点"部署"，顺着 USB 线搬进你的板子。拔线也忘不掉。

> 训练要排队，先拍完的先训。等着的时候想一个问题：**老师课前那堆"怪照片"（只拍一个角度、背景乱），会教出什么样的学生？**

部署成功后，拍一张"模型在板子上跑"的照片，并记下：

- 我训练了 ___ 类，每类各 ___ 张，训练等了大约 ___ 分钟。

### 第 4 步：换位互测——你的模型认得出别人的手吗

和同桌交换板子。规则：

1. 只准出剪刀石头布，变着花样出：远一点、快一点、换只手；
2. 认出一次得 1 分；
3. **认错一次……也记下来——那是宝贝**（在哪个出法下认错的）。

> 刁难只限"给它看东西"——不碰硬件、不遮镜头、不拔线。

### 第 5 步：归因——它为什么会认错

全班统计"翻车率"。然后每人写一张便签贴白板：

> **我的模型在 ______ 情况下认错。**
> （"光线暗就错" ✅ 合格；"它不准" ❌ 不合格——越具体越好。）

落点一句话：**它不笨，是你教得少。**想让它聪明，喂它更多、更不一样的例子。对会认东西的 AI，例子就是全部——说没有用，得给它看。

**写在这里：**

- □ 我的模型能认出我自己的三种手势
- 我的模型在 ______ 情况下认错（照抄你贴上白板的那句）

## 七、下半场：认出它 → 让它动起来

### 先懂一个概念：你的板子已经是"视觉 AI 传感器"

部署好模型的 XIAO，就是一个传感器——跟光线传感器、按钮一样，只不过它"感觉"的是画面。它认了东西，结果得有出口：

- **串口（UART）**——连着电脑时你在屏幕上看到的识别结果，走的就是它（今天联动就用它）；
- **I2C、SPI**——板子和板子之间说话用的（双板玩法，以后的课）；
- WiFi/MQTT——联网课再玩。

记住这个感觉：**认出 → 输出 → 别的家伙接住了干活。**

### 命题

认出剪刀 → 亮红灯；认出石头 → 蜂鸣器响；认出布 → 全灭——这是老师的示范，**你的规矩自己定**。想换语义尽管换：剪刀＝妹妹的暗号，认出就放她喜欢的音乐——你的模型你做主。

输出件：LED＋蜂鸣器打底；舵机/灯带每桌两件，先到先得。它"想事情"慢半秒——正常。

### 三格单（今天多一个新成员）

| 格 | 填什么 | 你的答案 |
| --- | --- | --- |
| 感知 | 摄像头认出的类别（scissors / rock / paper） | |
| 逻辑 | 认到哪类，干什么 | |
| 输出 | 灯、铃、或者你抢到的舵机 | |
| ⭐认不出时 | **认不出、或者不确定的时候，怎么办？** | |

新成员是必答题。写"什么都不做"也算答案——但必须是**你的决定**，不是它的意外。

> 它每次会报一个"把握有多大"的百分数（这个数叫**置信度**）——可以定：低于 70% 就当它认不出。填完给助教看一眼再动手。

### 联动句式（照抄，发给 Codecraft）

```text
我的 XIAO ESP32S3 Sense 上已经部署好一个图像分类模型，
能识别三类：scissors、rock、paper，识别结果和置信度会从串口输出。
请帮我写一个程序：
1. 读到识别结果是"scissors"且置信度高于 70% → 点亮 LED；
2. 读到"rock"且置信度高于 70% → 蜂鸣器响一声；
3. 读到"paper"或者置信度低于 70% → 全部熄灭（这就是"认不出时"的处理）。
先只实现第 1 条，跑通了我再来要第 2、3 条。
```

**老纪律：一次只要一步**——第 1 条跑通，再发第 2、3 条，不要三条一起发。报错了？把错误信息原样发回去，让它自己修。上传没反应？口诀：**滑一下**（板子侧面开关滑一下、再滑一下）。

左 SenseCraft 右 Codecraft，两个标签页别合并。类别名保持英文。

### 一类都没跑通？保底句式

```text
我的 XIAO ESP32S3 Sense 上已经部署好一个图像分类模型，
能识别三类：scissors、rock、paper，识别结果会从串口输出。
请帮我写一个最简单的程序：
读到识别结果是"scissors" → 点亮板载 LED。
```

保底版只做板载 LED，不额外接线——跑通建立信心，再接灯接铃扩展。

**写在这里：**

- □ 我的三格单填完了（含"认不出时"栏），助教看过
- □ 跑通了：认出 ______ → ______（今天的验收线）
- 我想刁难自己作品的三个场景（有余力写在三格单背面）：______

## 九、加餐（附录）：让硬件听指挥——Codecraft 输出件实操

> 对应 PPT 附录 23 页（页码 A·01–A·23）。正篇教会板子"**认**"，这份加餐教会它"**动**"——灯、铃、风扇，都是它的手。这些输出件的基本功，结业项目直接用得上。
> 工具只有一个：**Codecraft**（浏览器打开 codecraft.seeed.cc，不用安装）——你对它说人话，它替你写代码。

### 先认全你的套件

套件全家福对照实物逐一点名：主板、扩展板、摄像头、LED、蜂鸣器、风扇、旋钮、Grove 线——**认不全，不开工**。

### 接线三步 + 口诀

1. 将摄像头拔下来；2. 将排针长的那边插进小孔；3. 对准底下的基座，用力按下去。

- **口诀**：D1 = LED 小灯，即左上接口。
- **供电确认**：Type-C 插上电脑 → 看板子上的充电指示灯 → 灯亮 = 供电正常；不亮先换线。

> 为什么先学接线？模型认出东西后，指令要走这些线才能到灯和铃——线接不对，后面全是白忙。

### 连不上？按这个顺序查

1. 检查线材——用能传数据的 USB 线，不是只能充电的线；
2. 检查连接——线插紧、插对口，扩展板按到底；
3. 检查浏览器——Chrome / Edge 新版，串口弹窗点「允许」；
4. 检查板型——Codecraft 里选的是 XIAO ESP32S3。

> **2 分钟搞不定：换线 → 换板 → 找助教。**不现场硬修，时间留给做东西。

### Codecraft 上手四步

① 选板型：XIAO ESP32S3 → ② 连接串口（弹窗点「允许」）→ ③ 对话框说清你要什么 → ④ 生成 → 编译 → 烧录。

**成功标志**：板子按你说的做出反应——第一次「点亮」达成。你是导演，它是 crew。

### 三个任务：灯 → 铃 → 风扇（一步加一个硬件）

> **规则只有一条：在原对话里补新要求——命令 AI 迭代，不是推倒重来。**

| 任务 | 为什么做 | 你的指令 | 成功标志 |
| --- | --- | --- | --- |
| 一 · 点亮 LED | 灯最便宜、最诚实——程序对不对，一眼看见 | LED 灯珠插进 D1（小贴片是正极→插 +，大贴片是负极→插 D1）；对 Codecraft 说"帮我点亮 D1 上的 LED" | D1 的 LED 按你说的亮 / 灭 |
| 二 · 加入蜂鸣器 | 灯只能看，铃能听——看不见它的时候，让它出声叫你 | "Buzzer + LED 同步：蜂鸣器和 LED 一起响/停" | LED 亮蜂鸣器响，LED 灭蜂鸣器同步关 |
| 三 · 驱动风扇 | 从「亮」「响」到「转」——信号变成物理动作的第一步 | "在同一个项目里，加上让风扇转动的功能" | 3 个硬件同时工作：LED 持续亮 + Buzzer 每 2 秒响 + 风扇随机开关 |

> 风扇转得慢或断断续续？它是 5V 设计，3.3V 下扭矩偏弱——**供电问题，不是代码问题。能转动 = 任务完成。**

### 终极实战：旋钮控速（感知 → 逻辑 → 输出）

前面都是你命令它动；这次让它有"感觉"——旋钮是输入、风扇是输出，合起来正是三格单的完整闭环。

- **接线**：旋钮传感器用 Grove 线接扩展板 **A0** 端口；完整接线：D1 = 风扇，D2 = 蜂鸣器，A0 = 旋钮。
- **成功标志**：拧动旋钮 → 风扇速度从停止到全速随之变化；同时黄灯依然闪，蜂鸣器依然每 2 秒响一次。

### 高阶 Debug 指南

- **风扇嗡嗡不转**：PWM 输出较低 + 3.3V 供电，不足以克服静摩擦力——轻推一下扇叶试试。
- **代码报错**：某些旧版 ESP32 支持包没有标准 `analogWrite` 函数，要用 `ledcWrite`——不用背，**把报错原样发给 Codecraft** 就行。
- **Vibe 精髓**：报错不是失败，是给 AI 的下一句提示——复制给它，它会自己修正再烧录。
