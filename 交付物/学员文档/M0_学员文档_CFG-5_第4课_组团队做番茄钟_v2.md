_柴火创客学园 M0 · 零基础智能硬件入门_

## 一、这节课你会带走什么

上节课你的作品有了脸和手。今天，你给 AI 组一个团队——从一句话干活，升级到一支队伍帮你从头做完一个完整项目。

下课的时候，你会有五样东西：

1. **一个会跑的番茄钟**——在你的 Wio 上，专注、休息、提醒俱全，而且**有一处和所有人不一样**；
2. **一套五轮接力句式**——PM、设计师、架构师、开发、测试，五段开场白全在这份文档里，照抄就能用；
3. **一个方法：BMAD**——开源、免费、全世界开发者都在用的现成做法，今天它在你脑子里跑通一遍；
4. **一个归档文件夹**——五轮接力的截图，你人生中第一个完整项目的全程记录；
5. **一条 AI 日志**——四句照旧，今天必须写清一句：我的钟哪里不一样。

先说清楚这节课的玩法：**老师引导＋这份文档＋AI 对话 → 你自己的作品和记录。**每一步老师让你写的东西，都写在这份文档上（用电脑的就记在 md 文档里，手写的就写在纸上）——下课要交，后面几节课都要用。

## 三、为什么需要 BMAD：直接写 vs 先规划再写

你已经会让 AI 一句话帮你做东西了——小项目这么干，够用。但下面三件事，你大概率遇到过：

- 代码越来越长，想加个新功能，不知道让 AI 改哪里；
- 做到一半发现，一开始根本没想清楚；
- 想换个配色，不知道颜色藏在哪。

这不是你的问题，是"一句话全包"这种做法的天花板。课上对比了两种做法：

| | 方式 A：直接让 AI 写 | 方式 B：先规划再写 |
| --- | --- | --- |
| 结果 | 能跑，但仅此而已 | 界面是设计过的，结构是清楚的 |
| 加功能 | 容易乱，不知道改哪 | 知道往哪加 |

**方式 B 不是多了几步麻烦事——是让 AI 分几步帮你想清楚。**

### 认识 BMAD：开源、免费、专业的现成做法

这个做法有个正式名字，叫 **BMAD**（AI 驱动敏捷开发方法）。你只要记住三件事：

1. **开源免费**——全部文档和代码都在 GitHub 上公开，谁都能用，不花一分钱；
2. **全世界开发者都在用**——专业团队总结好的方法，里面有十几个专业角色、三十多个现成工作流；
3. 核心就一招：**不让 AI 一句话全包，让它扮演不同角色，分步帮你想清楚再动手。**

地址在这，可以自己查证：https://github.com/bmad-code-org/BMAD-METHOD

**BMAD 不是要装的软件，是一套方法。方法不用装——学会就是你的。**

以后你在自己电脑上做项目，想配上完整的 AI 团队，不用背命令，让 AI 帮你装——对它说：

```
帮我阅读 https://github.com/bmad-code-org/BMAD-METHOD 的文档，
在我的项目里配置好 BMAD 工作流。
```

AI 会自己读文档、自己跑安装（需要 Node.js 环境）。今天不弄这个——今天只用第一种用法：什么都不装，用下面的五轮句式。

## 四、你的团队：五个角色，都有名字

| 角色 | 名字 | 管什么 |
| --- | --- | --- |
| PM（产品经理） | John | 管"解决什么问题、给谁用" |
| 设计师 | Sally | 管"长什么样、怎么操作" |
| 架构师 | Winston | 管"分几块、有什么状态" |
| 开发 | Amelia | 管"写出来" |
| 测试 | Quinn | 管"挑毛病" |

原来你一个人乱干的事，现在是五个专家分工。**而你，是这个团队的老板。**

用他们之前，记住三条规矩：

1. **五轮在同一个对话里**——换角色不换窗口，直呼名字派任务就行，像给同事派活。中途开新对话，前面的结论就全丢了；
2. **每轮开场第一句："基于上一轮的结论"**——把上一段的结果交给新角色。这是接力赛，棒不能掉（第一轮没有上一轮，就从你的难题说起）；
3. 对话里还是那五条老规矩：一次一件事、说清输入输出、给它举个例子、不对就补充、看不懂就问它。

## 五、开题：番茄钟＋"必须有一处不一样"

番茄钟：专心 25 分钟，休息 5 分钟，再来一轮。就这么简单。今天每个人都做一个——用这个团队，在你手里的 Wio 上做。

但有一条规矩——**你的番茄钟，必须有一处和所有人不一样。**

这一处不能是"我的是蓝色的"这种，它必须从你的生活里长出来：你写作业老走神？你练琴要计时？你想做一个给妹妹用的？

告诉你一个秘密：AI 给所有人的默认答案都一样。**你的生活细节，是它给不了的那部分——那就是你的钟值钱的地方。**

（屏幕显示内容一律用英文、数字或图形——板上中文字库不稳，不赌中文渲染。）

## 六、五轮接力：把你的番茄钟做出来

五轮开场白全文都在这，照抄、填上你的内容就能用。**句式给结构，内容必须自己填——括号里空着发不出去。**

### 第 1 轮 ｜ PM · John：想清楚要什么

PM 不急着做，先问清楚——今天问的对象是你自己：我真实的专注难题是什么？

```
John，我要做一个番茄钟，解决这个难题：
（一句你生活里真实的事，比如：我写作业不到 10 分钟就想玩手机）
先问我 5 个问题，搞懂我要什么，再帮我写下：
这个钟必须做到的 3 件事。先别写代码。
```

John 会先问你几个问题——如实回答，别嫌麻烦。这是让你想清楚，不是直接给你一个糊弄的方案。

三个提醒：

- 他给的 3 件事里，**必须有你的"不一样"**。没有？追问他："我还没说我的特别要求——我走神的时候它该怎么办？"
- 清单贪多（什么功能都想塞）？用一句专业话收口：**"太复杂了，只保留 P0。"**（P0＝第一版必须有的。）
- 纠结难题选哪个？随便定一个，先做——做完一个你就知道第二个怎么做了。

**写在这里：我的钟必须做到的 3 件事**（其中一条标星——那是我的差异点）

> 1. ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
>
> 2. ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
>
> 3. ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿

### 第 2 轮 ｜ 设计师 · Sally：设计长什么样

开场第一句照旧——基于上一轮的结论。上节课练过的"位置、大小、颜色"，今天自己组织语言说进去：

```
Sally，基于上一轮的结论：我的钟必须做到这 3 件事：（抄上）。
帮我设计：
1. 计时中画面长什么样；
2. 休息中画面长什么样；
3. A、B、C 三个键各干什么。
我的特别要求：（你的差异点），画面上要体现。先别写代码。
```

觉得哪里不好，直接跟她说——"时间数字再大一点""换深色背景"。

**写在这里：**

> 计时中画面：＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
>
> 休息中画面：＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
>
> A 键＿＿＿＿　B 键＿＿＿＿　C 键＿＿＿＿

### 第 3 轮 ｜ 架构师 · Winston：出技术方案

动手之前，先听老师讲一样东西：**状态**。红绿灯见过吧？红的、绿的，一次只亮一个——时间到了就变。你的番茄钟也是这种东西：它有几种"样子"，一次只在一种样子里，有个动作让它变样子。

**现在，在纸上画你的钟的状态圈**：最少两个圈——专注、休息，箭头写上"什么让它变"（按 A 键／时间到了）。画不出三个圈没关系，两个圈就是完整的番茄钟。"暂停"是最常见的第三个圈，想要就加上。

画好了，让 Winston 出方案：

```
Winston，该你了。
照上面的需求和设计，给番茄钟做个技术方案，保持简单——
后面 Amelia 照着它写代码。
```

**方案细节你看不懂没关系——它不是给你看的，是给写代码的 Amelia 看的。**

**写在这里（状态圈画在纸上，或在这里写两行）：**

> 我的状态：＿＿＿ → ＿＿＿，什么让它变：＿＿＿＿＿＿

### 第 4 轮 ｜ 开发 · Amelia：一次做完整

前面三轮，需求、设计、方案都在这段对话里——Amelia 照着它们，一次把整个番茄钟做出来：

```
Amelia，基于前面的需求、设计和技术方案，把这个番茄钟完整做出来，
给我能直接用的代码。
为了方便测试，工作时间先设 1 分钟，休息 30 秒。
```

（为了方便今天测试，先设短一点——跑通了再改成你要的 25 分钟。）

拿到代码，上传，跑通。三个提醒：

- **报错了？把错误信息原样发回给 Amelia——它写的代码，它自己会修。**
- 上传没反应？想起桌上那句口诀——**没反应？滑一下**（侧面开关滑一下、再滑一下，进烧录模式）。
- 跑通了？再提一个你自己的改动——换个背景色、加个过渡动画——这就是**迭代**。

**实在跑不通**：举手找老师拿"救生句"，一字不改发给 AI，先让屏幕亮起来，再让 Amelia 在这之上补回完整功能。

### 第 5 轮 ｜ 测试 · Quinn：把它玩坏

测试工程师的工作只有一个：**把它玩坏。**

```
Quinn，我的番茄钟做好了。
帮我挑毛病：给我 5 个"把它玩坏"的测试方法，比如快速连按、计时到一半乱按键。
我逐个亲手试。
```

玩坏清单试完，再请一位特别的考官出场——**挑剔用户**。让 AI 扮演你构思单上那个真实的人，只挑一个刺：

```
请扮演＿＿＿（构思单上的真实人名），用一用我的番茄钟，
给它挑 1 个刺，只挑 1 个。
```

每试一条、每听一刺，做一个决定：这毛病**接受还是拒绝**？拒绝的，让 AI 修；接受的，写进"我知道它有这个小毛病"——这也是专业决定。修 bug 别修到停不下来：**修最重要的那一个，剩下的写进"以后再做"清单。**

**写在这里：玩坏清单 5 条，每条后面写"接受／拒绝"＋一句理由；挑剔用户那一刺单独记一句**

> 1. ＿＿＿＿＿＿＿＿　→　接受／拒绝，因为＿＿＿＿＿＿
>
> 2. ＿＿＿＿＿＿＿＿　→　接受／拒绝，因为＿＿＿＿＿＿
>
> 3. ＿＿＿＿＿＿＿＿　→　接受／拒绝，因为＿＿＿＿＿＿
>
> 4. ＿＿＿＿＿＿＿＿　→　接受／拒绝，因为＿＿＿＿＿＿
>
> 5. ＿＿＿＿＿＿＿＿　→　接受／拒绝，因为＿＿＿＿＿＿
>
> 挑剔用户挑的刺：＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿

## 七、收束：三件比彩蛋重要的事

### 第一件：归档——你人生中第一个完整项目的全程记录

把今天五轮接力，每轮截一张图，五张图放进一个文件夹，写上你的名字和日期。这个文件夹是你的宝贝——以后你想知道"一个完整项目长什么样"，看的就是它。哪一轮忘了存，课后补截，文件夹里贴张纸条写"这轮后补"。

### 第二件：迁移——这套方法只能用来做硬件吗？

这门课的教案，就是老师用这五个人写的：PM 定每节课解决什么问题，测试挑教案里的坑。轮到你了：写研究性学习报告呢？那里的 PM 是谁？架构师呢？测试呢？

**写在这里：**

> 这套方法我还能用在＿＿＿＿＿＿＿＿，那里的 PM 是＿＿＿＿＿＿＿＿。

### 第三件：一句话收束＋今天的日志

**BMAD 这五个角色，不是做硬件的方法，是做任何事的方法——今天先拿硬件练手。**五角色不是每次都要全用：小作品合并着用就行——**项目多大，团队多大。**

再看一眼你们走过的这条路——10 年前，"让 LED 亮"就算入门；5 年前，"连上 WiFi"是高阶；今天，零基础的你，一节课带着五个角色做完了一个完整项目。

**今天的日志，四句照旧——必须写清一句：我的钟哪里不一样。**

第 1 步：**拍一张**你的番茄钟（只拍手和板子）。

第 2 步：**说三十秒，四句说全**：

```
做了＿＿＿＿；
卡在＿＿＿＿；
后来＿＿＿＿；
我的钟哪里不一样：＿＿＿＿。
```

第 3 步：**让 AI 整理，你来校对。**说完发给 AI：

```
帮我整理成日志，只许整理我说过的，不许加我没说的。
```

它整理完，**你必须看一眼再确认**——AI 会一本正经地编，校对是你的事，谁也替不了。

**写在这里：今天的日志（校对后的版本）**

＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿

## 八、缓冲时间：先达标，再放飞

课堂最后有一段机动时间，听老师宣布怎么用：

1. **补达标（人人必须过线）**：番茄钟主体还没跑通的，继续做完——这是今天必须过的线；
2. **彩蛋挑战（过了线的领）**，先想清楚"做还是不做"，两分钟决定，不纠结：
   - **反扣计时**——板子翻过来就开始计时（这块板子能感觉到自己被翻过来）；
   - **胜利音乐**——连续完成 3 轮，响一段；
   - **休息冷笑话**——休息画面显示一句英文冷笑话；
3. **帮同桌**：只能动嘴，不能碰他的键盘。

彩蛋做不出来，不影响今天的过关——把它写进"以后再做"清单，那也是成绩。

**写在这里（做了彩蛋的同学写）：**

> 我给钟加的彩蛋是＿＿＿＿＿＿，做成了／没做成，进"以后再做"清单了。

## 九、收尾：看清你今天走过的路

白板上有一张地图，八个框，是做一个项目的完整地图。今天你已经亲手走过了前六个：

1. 想明白给谁做、解决什么——PM 干的；
2. 找到真实的人——你的挑剔用户；
3. 说清楚要什么、拆成小块——设计师和架构师干的；
4. 跟 AI 一起实现——开发干的；
5. 做出来试试、挑毛病——测试干的；
6. 修还是忍、砍还是留——你刚才"接受还是拒绝"、彩蛋"做还是不做"，就是这一步。

七八两步今天只起了个头：做出来给谁看——你们互展；做完回头看——就是现在。
