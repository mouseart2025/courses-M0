## 一、态度声明：这套交付物，欢迎"魔改"

**先亮明立场：这套交付物，从设计的第一天起，就是给你改的。**

原因很简单，这门课教的道理，对课件本身同样成立：

- 课堂上我们告诉学生——**代码让 AI 写，你负责出题、判断、拍板**；
- 对老师我们也想说——**课件让 AI 改，你负责定方向、做取舍、把质量关**。

所以我们对你的期待不是"照本宣科"，而是"大胆改写"。具体说：

1. **你可以把交付物作为 AI 的上下文**。把 `交付物/` 文件夹（或你需要的某几课）连同本指南交给任意 AI / Agent，让它在理解课程的基础上，帮你改造成你的版本。
2. **改什么都可以**。时长、对象、硬件、语言、例子、节奏、篇幅——都改。只有一条脊柱不能动（见 3.1 与 3.4：学生指挥 AI、老师只巡不教等教学法内核），那是这门课的立身之本。
3. **改了也不用藏着**。如果你做出了漂亮的改编，欢迎按第六节把好的版本回传给我们——我们乐意署名收录，让更多人受益（这也是我们与合作方协议里写明的机制）。
4. **法律上，我们给了你明确的授权**：交付物以 **CC BY 4.0** 开源协议发布——署名即可，商用、改编、给 AI 用都可以。详见 `LICENSE.md`。

> 用一句话收口：**这套东西不是围墙，是地基。请在上面盖你自己的房子，并告诉我们你盖出了什么。**

## 二、给老师的三分钟导读（人读）

### 2.1 交付物里有什么

```
交付物/
├── 学期交付清单.md        ← 先读这个：每课用哪三个文件、课前要备什么、全课通用口径
├── 教师课件/              ← 讲师版（每课一份，流程+话术+时间轴，老师照讲）
├── 学员文档/              ← 学生版（每课一份，任务+提示词+句式，发给学生）
├── 演示文稿/              ← PPTX（每课一份，投屏用；第6/8/9/10课另有可编辑 pptd 工程）
└── LICENSE.md             ← 开源协议（本指南的配套文件）
```
素材（封面插画、板子图、案例照片等）在仓库根的 `素材/` 目录；英文本地化版本在 `交付物_EN/`。

### 2.2 每课三件套怎么配合

每课上课只用三个文件：**讲师版**（你照着讲）→ **PPTX**（你投屏）→ **学员文档**（发给学生，共享只读）。三者关系：

```
讲师版（内容权威：流程、话术、时长、预案）
   ├── 对齐 → 学员文档（学生视角：任务、提示词、句式）
   └── 对齐 → 演示文稿（投屏视角：页面、投屏句式）
```

**改的时候三者要联动**：改了讲师版的口径，学员文档和 PPT 也要同步，否则老师和学生看到的是两套说法。

### 2.3 课件里自带的"可替换位"

每份讲师版/学员文档里都预留了本地化接口，改课件先找它们：

- **本地化替换位**（如第 0 课第七节）：讲师自我介绍、作品案例、学生生活例子——表格列明了"默认内容 → 可替换为"；
- **时间松紧带 / 可压不可压**：每课标明哪些环节能压缩、哪些不能（记忆点）；
- **翻车速查表**：现场状况与处理话术，按你的环境补充；
- **讲师反馈页**：课后 10 分钟填写，是下一轮改进的输入——也可以让 AI 帮你填。

### 2.4 不想自己改？三种交给 AI 的用法

| 用法 | 怎么做 | 适合谁 |
| --- | --- | --- |
| **A. 全文交底** | 把 `交付物/` 文件夹 + 本指南一起拖进 AI 对话，用 3.6 的提示词模板提出要求 | 想大改（换对象/换硬件/换语言） |
| **B. 局部手术** | 只把某一课的三件套 + 本指南交给 AI，让它只改指定部分（如"第 3 课压缩成 40 分钟"） | 只想微调某一课 |
| **C. 当教练** | 不交文件，只把本指南交给 AI，让它针对你的环境提问、给改造建议 | 还在犹豫改什么 |

## 三、给 AI 的话：把交付物改造成"你的课"

> 本节是写给**接收本文件的 AI / Agent** 的。收到本指南时，请先完整读一遍本节，再读你被分配处理的交付物文件。

### 3.1 先建立背景：M0 是什么

**课程定位**：柴火创客学园《M0 · 零基础智能硬件入门》，面向零基础学员（中学生为主，也适配高校通识/企业内训），从点亮第一块开发板走到学员自己的作品。核心方法是**氛围编程**——学员说中文、AI 写代码，学员不手写一行代码；以及 **BMAD**——给 AI 分角色（PM/UX/架构/开发/测试），把 AI 当团队用。十次课学期班（CFG-5）：第 0 课先导课（宣讲）+ 第 1–10 课正课，第 7 课起进入学员自己的立项与"马拉松"（MVP → 请外援 → 冲刺路演）。

**教学法"脊柱"（不可动，见 3.4）**——这是这门课的立身之本：

1. **学生是导演，AI 是程序员**：严禁学生手写代码；学生的活只有三件——**说清楚、看效果、不满意让它改**。
2. **老师只巡不教**：学生看文档、和 AI 沟通完成任务；讲师管过程控制与方向引导。学员卡住的默认话术是"**先问问你的 AI**"。
3. **合作节奏三步法**：说清楚 → 看效果 → 继续改。配套两句咒语：**"一次只说一件事"**、**"不对，就往下补一句"**（别重开对话，让 AI 记得上下文）。
4. **三格图思维**：**感知 → 逻辑 → 输出**。任何作品先想清三格、说给同桌听，再动手。
5. **项目式主线**：八步项目法 + **六样能力**（会出题、会找用户、会做出来、会取舍、会判断好坏、会讲给别人听）。
6. **成长史日志**：每课"拍一张、说三十秒"（今天我做了／卡在／后来／下次），结课汇成作品 README——**成长史比作品值钱**。
7. **报错三连**：把报错整段复制 → 贴回给 AI → 加一句"我刚才做了什么"。**报错不是坏了，是 AI 在跟你说话**。

**全课通用口径**（来自《学期交付清单》，任何课次改造都不得破坏）：

- **零打印**：所有提示语/句式在 PPT 或学员文档里，不打印物料；
- **无统一休息**：学生按自己节奏，不设统一休息；
- **不写死时刻**：讲师版只给时长与相对节点（如"下课前 15 分钟必进仪式"），按实际上课时间推算；
- **老师只巡不教**（同上）；
- **合影纪律**：只拍手、不拍脸（举作品/举手/背影），影像公开需家长授权——**安全与伦理口径必须保留**。

### 3.2 交付物地图：怎么读这套文件

- **先读《学期交付清单.md》**，再读目标课的**讲师版**（不是学员文档，也不是 PPT）——讲师版是内容权威。
- **命名规则**：`M0_教师课件_CFG-5_第N课_课名_vX.md`、`M0_学员文档_CFG-5_第N课_课名_vX.md`、`M0_演示文稿_CFG-5_第N课_课名_vX.pptx`。`vX` 是版本号，改版必须升号并在文档头/页脚写修订说明。
- **三件套关系**：讲师版（流程+话术+时间轴+预案）→ 学员文档（学生视角，任务+提示词+句式，通常照抄讲师版的投屏原文）→ 演示文稿（页面级，投屏句式逐字一致）。
- **讲师版的自带结构**（读文件时按此定位）：课前准备 → 课程总览表 → 分段流程（🗣️ 逐字话术）→ 双保险/降级预案 → 翻车速查表 → 句式与投屏原文 → 本地化替换位 → 讲师反馈页。
- **信源优先级**：用户手改过的 PPTX 即定版（唯一事实来源）；讲师版其次；学员文档/PPT 策划用于对齐，不再反向改成品。

### 3.3 改造方法论：六步作业法

收到改造任务后，按下述六步走，**不要跳步、不要直接重写全文**：

**第 0 步 · 建立全局。** 先读《学期交付清单.md》+ 目标课讲师版，明确原课的环节、时长、话术与口径，再谈改造。不基于印象动手。

**第 1 步 · 摸清约束。** 如果用户没给全，先列出并补问以下必问清单（问完再动手）：

| 维度 | 必问项 |
| --- | --- |
| 对象 | 年龄段/学段、人数、是否有编程基础 |
| 时间 | 总时长、课时数、单课时长、排课节奏（每周/集中） |
| 场地 | 线下/线上、机房还是自带设备、网络条件、是否有投影 |
| 硬件 | 沿用 Seeed 套件（Grove Beginner Kit/Wio Terminal/XIAO ESP32S3 Sense）还是换平台 |
| 账号 | 是否有 Codecraft 席位/本地版 aily-blockly/外网访问 |
| 语言文化 | 授课语言、受众文化场景（学生生活例子要本地化） |
| 目标 | 体验课/学期班/比赛辅导/企业内训/高校学分课 |
| 交付形态 | 只要讲师版？还是三件套都要？是否含 PPTX |

**第 2 步 · 识别脊柱与变量。** 用 3.4 的清单把"不可改（脊柱）"和"可改（变量）"分开。脊柱原样保留；变量列出改动方案。

**第 3 步 · 先交"改造清单"，再动手。** 动手改正文之前，先给用户一张对照表（`原 → 改 → 理由`），说明你打算动哪些、不动哪些、为什么。**用户确认后再改正文**。这是本方法论最重要的一步——避免把判断成本丢给用户、也避免你改偏方向。

**第 4 步 · 三件套联动改造 + 一致性维护。** 改讲师版 → 同步学员文档 → 同步 PPT。维护一致性：同一句式、同一时长算法、同一课名、同一口径；保留每课的"可压/不可压"标记；数字与时长的口径要可追溯（不写死时刻的规矩不能破）。

**第 5 步 · 过质量关卡。** 改完自查两关：
- **新老师关**：一位无编程背景的老师冷读（拿到不预习）照讲，会不会卡壳？逐字话术是否完整？
- **零基础学员关**：零基础学员看学员文档，任务是否明确、提示词是否可用、会不会被术语劝退？
再核对：全课通用口径（零打印/不写死时刻/合影纪律）有没有被破坏；本地化替换位有没有遗漏。

**第 6 步 · 验收交付。** 按新命名与版本号输出；交付说明里列明：**我改了哪些、没改哪些、哪些是待用户拍板项**。不要只交付"结果"，要把"判断"也交出来。

### 3.4 可改 vs 不可改

| 类别 | 内容 | 说明 |
| --- | --- | --- |
| 🔒 **不可改（脊柱）** | 严禁手写代码、学生指挥 AI（说清楚→看效果→继续改） | 改了，这门课就不是"AI 时代的课"了 |
| 🔒 **不可改** | 老师只巡不教、"先问问你的 AI" | 讲师角色的立身之本 |
| 🔒 **不可改** | 三格图（感知→逻辑→输出）、两句咒语 | 全课通用的思维脚手架 |
| 🔒 **不可改** | 成长史日志仪式（拍一张说三十秒→README） | 课程差异化价值 |
| 🔒 **不可改** | 安全/伦理口径：合影纪律（只拍手不拍脸）、影像公开需家长授权 | 未成年人保护红线，任何改编不得弱化 |
| 🔒 **不可改** | 署名与许可（CC BY 4.0，见 LICENSE.md） | 法律义务 |
| 🔓 **可改** | 时长、课时数、时间轴、环节松紧 | 按你排课重排 |
| 🔓 **可改** | 硬件平台、工具链（Codecraft/aily-blockly/其他） | 换平台要联动重写提示词与演示预案 |
| 🔓 **可改** | 语言与文化场景（学生生活例子、家长话术） | 参照 `交付物_EN` 的本地化方法论：本地化≠直译 |
| 🔓 **可改** | 学员年龄段、难度、篇幅、节奏、附录 | 面向你的对象 |
| 🔓 **可改** | 案例（Brandy/Neil 等可替换为本地案例，但要讲得出"怎么跟 AI 说的"细节） | 替换位已留好 |

> 如果用户要求改"不可改"项（例如要求学生手写代码），请先说明这样做的代价与这门课精神的关系，让用户知情决策——但最终以用户拍板为准。

### 3.5 输出规范

- **命名**：沿用 `M0_教师课件_CFG-5_第N课_课名_vX.md` 风格；你自己的品牌可换前缀，但必须保留"讲师版 / 学员文档 / 演示文稿"三件套的对应关系，让人一眼能配对。
- **版本**：改版升号，文档头/页脚写一行修订说明（参考现有文档页脚的"修订说明"体例）。
- **一致性**：三件套同一句式、同一时长算法、同一课名；不写死时刻；新增数字要给出处或标注估算。
- **保留接口**：讲师版保留"本地化替换位"表和"讲师反馈页"——它们是下一轮 AI 改造的接口。
- **不编造**：新增案例/数据要可追溯；用户没给的信息标为"待补充"，不要编默认值硬填。

## 四、常见改造场景速查表

| 场景 | 典型改动 | 必须保住 |
| --- | --- | --- |
| **3 小时体验课** | 从十课里抽骨架（如第 0 课宣讲 + 第 1 课点亮 + 第 8 课 MVP 概念），压到体验时长 | 点亮名字、先问 AI、三格图 |

| **企业内训** | 案例换职场场景、强化"报错三连"与需求单、收在可演示产出 | 说清楚→看效果→继续改 |
| **换硬件平台** | 重写提示词、演示预演与物料清单；三格图框架不动 | 三格图、两句咒语 |
| **换语言/换国家** | 参照 `交付物_EN/01_Workflow` 的本地化方法论（本地化≠直译） | 教学意图、环节、时长守恒 |
