# 用 AI 改课・完整流程指南

*给老师，也给 AI ｜ 柴火创客学院・M0 零基础智能硬件入门（courses-M0 仓库） ｜ v1・2026-09-08*

> **一句话**
>
> ：拿到 courses-M0 这套开源课程后，怎么把它改造成 "你的课"？本文档给出一条可照做的五步流程 ——
>
> **说明需求 → AI 出大纲 → 大纲修订 → 逐课输出四件套 → 验收回传**
>
> ，每一步都配了可直接复制给 AI 的提示词模板和你的评审点。



***

## 〇、这份文档是什么、给谁用

### 0.1 它和《交付物使用指南》的分工

仓库根目录已有一份《交付物使用指南（给老师与 AI）》（`交付物/交付物使用指南_给老师与AI_v1.md`），它解决的是 "**怎么用这套交付物、怎么小步改造**"（六步作业法：建全局 → 摸约束 → 识别脊柱与变量 → 改造清单 → 联动改造 → 验收）。

本文档解决的是 "**从零改造一门课**" 的完整流程，适合两种场景：



| 场景                                       | 用哪份                  |
| ---------------------------------------- | -------------------- |
| 只想微调某一课（压缩时长、换例子、改硬件）                    | 《交付物使用指南》用法 B / 第三部分 |
| **从需求出发，让 AI 重新设计整门课**（换对象、换课时结构、从积木池重排） | **本文档**              |

两者共用同一套底层约定（教学法脊柱、全课通用口径、命名规范），本文档直接引用，不重复展开。

### 0.2 给谁读



| 读者                 | 读法                                   |
| ------------------ | ------------------------------------ |
| **老师 / 课程负责人（人）**  | 按第一至五章走流程，重点看每步的 "你的评审点" 和 "可复制的提示词" |
| **AI / Agent（机器）** | 收到用户粘贴的提示词模板时，按模板要求执行；本文档是你的流程总纲     |

### 0.3 一套内容池，支撑所有形态

courses-M0 是 "**积木式三层架构**"（详见《课程设计 Skill》）：



```
第 3 层：交付配置（对外卖的"课程产品"）—— CFG-0 快闪 / CFG-1 体验课 / CFG-2 一日坊 / CFG-3 两天短训 / CFG-4 六次课 / CFG-5 十次课 / CFG-T 师资培训

第 2 层：课次模板（一个 3h 标准课次的节奏骨架）—— 魔法时刻 → 概念注入 → 动手实操 → 分享收尾

第 1 层：教学积木（最小内容单元）—— X0–X9 通用积木 + A1–A3 / B1–B2 / C1–C2 硬件积木
```

**只有第 1 层是内容资产，第 2、3 层是拼装规则。** 改课的本质 = 按你的需求，从积木池重排出一条新的积木序列，再逐课产出四件套。这也是本文档 "AI 出大纲" 的理论基础。

└────────────────────────────────────────────────────────────────┘
```

**三条全局纪律（贯穿五步，违反任何一条都先停下）：**



1. **教学法脊柱不可动**：学生指挥 AI（说清楚 → 看效果 → 继续改）、老师只巡不教、三格图（感知→逻辑→输出）、成长史日志、安全 / 合影纪律（只拍手不拍脸、影像公开需授权）。改课只能改 "变量"，不能改 "脊柱"—— 完整清单见《交付物使用指南》3.4。

2. **全课通用口径不可破**：零打印、无统一休息、不写死时刻（只给时长与相对节点）、老师只巡不教、合影纪律。

3. **三件套联动**：同一句式、同一时长算法、同一课名；改了讲师版，学员文档和 PPT 必须同步。

## 二、第 1 步・说明需求（你填，AI 不替你填）

**这一步只属于你。** AI 再聪明也不知道你的学员是谁、你的场地什么样。需求说得越清楚，后面每一课返工越少。

### 2.1 需求说明书模板（复制后填写）



```
【课程需求说明书】

一、课程基本盘

&#x20; 1\. 课程名称（可后定）：＿＿＿＿＿＿＿＿

&#x20; 2\. 总时长：＿＿＿（如 3 小时 / 6 小时 / 30 小时）

&#x20; 3\. 课时结构：＿＿＿次课 × ＿＿＿分钟/次（或：一次性 / 集中营）

&#x20; 4\. 排课节奏：每周 1 次 / 周末集中 / 寒暑假营 / 其他＿＿＿

二、面向对象

&#x20; 5\. 年龄段/学段：＿＿＿（如 9–12 岁 / 中学生 / 大学生 / 成人）

&#x20; 6\. 预计人数：＿＿＿

&#x20; 7\. 编程基础：零基础 / 有一点 / 不设限

&#x20; 8\. 学员动机与预期：＿＿＿（如"暑期兴趣班""学校课后服务""企业团建"）

三、课程目标预期（最重要的一栏，请具体）

&#x20; 9\. 结课时学员带走什么？（可多选，按优先级排序）

&#x20;    □ 一个自己定义的作品

&#x20;    □ 完整的项目成长记录（日志/README）

&#x20;    □ "用 AI 完成整个项目"的信心与方法

&#x20;    □ 某项具体能力（出题/找用户/做出来/取舍/判断好坏/讲给别人听）

&#x20;    □ 比赛作品 / 升学材料 / 展示成果

&#x20;    □ 其他：＿＿＿

&#x20; 10\. 你不想要什么（同样重要）：＿＿＿（如"不要纯编程课""不要填鸭式讲解"）

四、教学环境

&#x20; 11\. 场地：线下机房 / 线下普通教室 / 线上 / 混合

&#x20; 12\. 设备：机房电脑（可装软件?） / 自带笔记本 / 无电脑

&#x20; 13\. 网络：可上外网 / 仅内网 / 不确定

&#x20; 14\. 投影/投屏：有 / 无

五、硬件与平台

&#x20; 15\. 硬件：沿用 Seeed 套件（Grove Beginner Kit / Wio Terminal / XIAO ESP32S3 Sense）

&#x20;     或 换平台（说明：＿＿＿）/ 还没定，请 AI 给建议

&#x20; 16\. 平台账号：有 Codecraft 账号体系 / 需本地离线方案 / 不确定

六、交付形态

&#x20; 17\. 你要什么：只要大纲 / 大纲 + 逐课四件套 / 四件套 + PPTX / 只要某一课

&#x20; 18\. 语言：中文 / 英文 / 双语

&#x20; 19\. 其他约束（文化场景、学校规定、预算、特殊学员等）：＿＿＿
```

### 2.2 需求不完整时的两种做法



* **你赶时间**：把上面模板填到 "能答的都答了"，未定的项写 "待定"，让 AI 在出大纲时按合理默认并**标注假设**（例："假设硬件沿用 Grove Beginner Kit"），你在大纲修订时逐条确认。

* **你还没想清楚**：把《交付物使用指南》的用法 C（当教练）交给 AI—— 让 AI 针对你的环境提问，你答完它帮你填表。

### 2.3 你的评审点（填完后自查）



* [ ] 时长和课次数是真实可行的（3 小时体验课 ≠ 30 小时学期班的内容密度）

* [ ] 目标预期写的是 "学员带走什么"，不是 "教什么内容"

* [ ] 硬件 / 网络约束如实填写（C 系列积木依赖外网，进校园前必须确认）

* [ ] 明说了 "你不想要什么"

## 三、第 2 步・AI 出大纲

### 3.1 给 AI 什么

把下面内容一起放进 AI 对话（任选一种组合）：



| 组合    | 放什么                        | 适合                   |
| ----- | -------------------------- | -------------------- |
| A（推荐） | 《课程设计 Skill》 + 《需求说明书》     | AI 基于积木池与配置矩阵专业重排    |
| B     | 整个 courses-M0 仓库 + 《需求说明书》 | AI 自己从交付物反推结构（更准但更重） |
| C     | 只放《需求说明书》 + 本指南            | 快，但 AI 不知道积木池细节      |

### 3.2 出大纲提示词模板（可直接复制）



```
你是 M0 课程设计专家。请基于我提供的需求，参照《课程设计 Skill》

（积木池 X0–X9 / A1–A3 / B1–B2 / C1–C2、配置矩阵 CFG-0～CFG-5、

项目全流程八环节 ①选题→②找用户→③做原型→④写代码→⑤取舍→⑥判断→⑦记录→⑧商业化）

输出一份课程大纲。

【我的需求】

（粘贴你的《需求说明书》全文）

【大纲输出格式】

一、课程定案：课名候选（过"一眼懂"测试：不看背景材料的人能说出这节课做什么）、

&#x20;  总时长、课次数、配置代号（对应哪个 CFG，或说明是新配置）

二、积木序列：按课次列出——每课用哪些积木（编号+名称）、每课主题、时长分配

三、八环节闭环核对表：整个课程覆盖哪些环节，逐课标注（硬规则：≥3h 必须覆盖

&#x20;  ①②④⑦；≥1 天补 ⑤⑥；≥6 次课必须八环节全覆盖，不允许只覆盖 ④）

四、每课一句话目标：学员上完这课带走什么

五、硬件与工具链需求：由积木序列推导出的设备清单与网络/安装要求

六、假设清单：我需求里没写清的项，你按什么默认处理的，逐条列出

【纪律】

1\. 先给"大纲草案"，不要直接开始写逐课内容；

2\. 遵循《课程设计 Skill》的硬规则：X7 转折课只进 ≥6 次课配置、短配置纯

&#x20;  Codecraft 轨道、C 系列需网络检查、最小流程闭环；

3\. 时长分配要符合真实课堂节奏（AI 任务几分钟出结果，不要排几十分钟）；

4\. 如果我的需求与某条脊柱冲突（如"要求学生手写代码"），先在假设清单里

&#x20;  指出代价，不要默默执行。
```

### 3.3 你的评审点（收到大纲后）



* [ ] 课次数 × 单课时长 ≈ 总时长

* [ ] 八环节闭环达标（对照上面 "硬规则"）

* [ ] 硬件清单在你的约束内（尤其外网 / 安装权限）

* [ ] 每课 "一句话目标" 是你想要的东西

* [ ] 假设清单里的默认值你都能接受

## 四、第 3 步・大纲修订（人机多轮，直到定稿）

**这是人机协作的核心环节，也是避免返工的关键。** 不要跳过大纲直接做逐课内容。

### 4.1 修订对话纪律



1. **一次提一批修改点**，不要一条一条挤牙膏：把对大纲的所有意见一次说完（或按主题分 2–3 批）。

2. **让 AI 给 "改了什么、为什么" 对照表**：每次修订后，要求 AI 输出 "原 → 改 → 理由" 三列，你只审变化，不用重读全文。

3. **冲突以你的需求为准**：AI 认为某条需求与脊柱冲突时，它指出代价，你拍板。

4. **改到 "可以动手" 就停**：大纲不需要完美，只需要每一课的目标、积木、时长、闭环都明确。

### 4.2 大纲修订提示词模板



```
请按下述意见修订大纲，输出"修订对照表"（原 → 改 → 理由），不要重发全文。

修订意见：

1\. ＿＿＿＿＿＿＿＿

2\. ＿＿＿＿＿＿＿＿

3\. ＿＿＿＿＿＿＿＿

修订后请重新输出：积木序列、八环节闭环核对表、每课一句话目标（这三项必须更新）。

如某条意见与课程脊柱（学生指挥 AI / 老师只巡不教 / 三格图 / 安全口径）冲突，

请先说明代价再等我确认。
```

### 4.3 定稿标准（三条同时满足即为定稿）



* [ ] 每一课：积木编号 + 课名 + 时长 + 一句话目标，无 "待定"

* [ ] 八环节闭环核对表无断链、无 "只覆盖 ④" 的课

* [ ] 硬件 / 网络 / 工具链清单你能落实

> 定稿后，让 AI 把定稿大纲存成一份独立文件（如 
>
> `M0_课程大纲_[你的配置名]_v1.md`
>
> ），后续每一课都引用它。
>
> **大纲是逐课生产的唯一依据。**



***

## 五、第 4 步・逐课输出四件套（每课严格按序）

大纲定稿后，**一课一课地做，不要一次生成全部**。每一课遵循固定四件套顺序：



```
① 教师讲义（讲师版 MD）——内容权威：流程、话术、时长、预案

&#x20;     ↓ （强制关卡：你确认内容）

② 教师 PPT 策划（策划文档 MD）——页面级：每页设计 + 讲稿

&#x20;     ↓ （强制关卡：你确认对外课名、页序、标题后才允许做 PPT）

③ 教师 PPT（PPTX）——按策划 + 品牌规范生成

&#x20;     ↓

④ 学生文档（学员文档 MD）——学生视角，任务 + 提示词 + 句式
```

> 说明：这份顺序与 courses-M0 内部生产流水线（
>
> `.agents/skills/m0-course-authoring`
>
> ）一致：② 由 ① 提炼而来、③ 由 ② 生成、④ 可与 ②③ 并行但口径必须与 ① 一致。

### 5.1 第 ① 件：教师讲义（讲师版）

**性质**：这节课的**内容权威**，其他三件都向它对齐。

**AI 产出要求**（依据《风格规范 Skill》与讲师版 G1–G8 规范）：



* 结构：课前准备 → 课程总览表（环节 / 时长 / 学员在做什么 / 你要做什么）→ 分段逐字流程（🗣️ 话术逐字写好）→ 双保险 / 降级预案 → 翻车速查表 → 句式与投屏原文 → 本地化替换位 → 讲师反馈页

* 口吻：单文档自包含（老师只读这一份就能上课）、人话命名、三色话术（🗣️ 念 / 👀 看 / ⚠️ 应对）、设计层零出现（积木编号等内部词只放页脚）

* 时长：用钟面时刻或相对节点，**不写死具体钟点**；标出 "可压 / 不可压" 环节

* 物料：零打印；物料三分类（起步包已含 / 需自备 / 可选加分）

**你的评审点**：重点看 —— 新老师冷读能否照讲？逐字话术是否完整？翻车预案是否符合你教室的实际情况？

### 5.2 第 ② 件：教师 PPT 策划

**性质**：页面级设计蓝图，由教师讲义提炼而来（不是从积木卡直接生成）。

**AI 产出要求**：



* 每页必含：页面类型、停留时间、设计说明、展示内容、讲师讲稿（🗣️ 口径与教师讲义一致）

* 设计规范：柴火品牌（白 70% / 黄 `#F3D230` 15% / 黑 10% / 红 `#D84144` 5%、无渐变无阴影、思源黑体、16:9、每页核心信息 ≤3 点、实操步骤一步一页大字）

* 页脚附 "用户确认点清单"，**对外课名候选列在第一位**（课名要过 "一眼懂" 测试）

**你的评审点（强制关卡）**：对外课名、页序、各页标题、页数与时长的匹配。**你确认前，AI 不得进入下一步做 PPT。**

### 5.3 第 ③ 件：教师 PPT（PPTX）

**性质**：投屏成品，逐页忠实执行已确认的策划文档。

**AI 产出要求**：



* 不临场增删页面、不改标题、不换配色

* 讲稿进备注页，不上屏；屏幕上只留投屏内容（提示语、句式、步骤）

* 零打印：所有提示语 / 句式都在 PPT 或学生文档里

**你的评审点**：逐页截图自查（配色比例、留白、每页 ≤3 点）、页数与策划一致。**如果你在 PPT 里手改定版，此后该 PPT 成为唯一事实来源**，教师讲义和学生文档按 PPT 口径回填同步（见 5.5）。

### 5.4 第 ④ 件：学生文档

**性质**：学生视角，自己能看懂、能照做。

**AI 产出要求**：



* 第二人称（"你"）；操作引导 + 填空记录区一体，每环节设 "写在这里" 的成果锚点（含＿＿空位）

* 本课用到的 AI 句式**全文可复制**（含＿＿空位，空由学员自己填）

* 与教师讲义口径一致：同一句式、同一课名、同一时长算法；不要把讲师话术原文搬进来

* 全文无 emoji（v2 体例）；标题过 "一眼懂" 测试

**你的评审点**：零基础学员看文档能否独立完成任务？提示词是否可直接使用？会不会被术语劝退？

### 5.5 三件套联动与版本



| 规则   | 说明                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------- |
| 命名   | `M0_教师课件_CFG-x_第N课_课名_vX.md` / `M0_PPT策划_…` / `M0_演示文稿_…_vX.pptx` / `M0_学员文档_…_vX.md`；课名用对外展示课名 |
| 版本   | 改版必升号，文档头 / 页脚写一行修订说明                                                                           |
| 联动   | 改讲师版口径 → 同步学生文档与 PPT；用户手改 PPT 定版 → 讲师版 / 学生文档向 PPT 回填                                           |
| 接口保留 | 教师讲义保留 "本地化替换位" 表和 "讲师反馈页"，它们是下一轮 AI 改造的接口                                                      |

### 5.6 逐课生产提示词模板



```

&#x20;  → 我确认课名/页序/标题后，再做 ③

## 六、第 5 步・验收与回传

### 6.1 质量关卡（每课交付前自查）



1. **新老师关（冷读测试）**：一位无编程背景的老师，拿到教师讲义不预习，照讲会不会卡壳？

2. **零基础学员关**：零基础学员看学生文档，任务是否明确、提示词是否可用？

3. **一致性硬指标**：四件套同一课名 / 同一句式 / 同一时长算法；全课通用口径（零打印 / 不写死时刻 / 合影纪律）没被破坏；本地化替换位无遗漏。

4. **闭环核对**：该课在大纲闭环核对表中的环节覆盖是否兑现。

### 6.2 整门课验收清单



* [ ] 逐课四件套齐全，命名符合规范，版本号连续

* [ ] 大纲闭环核对表里的每一课都有对应产出

* [ ] 任选 2 课 "干跑"：AI 模拟逐分钟走一遍，查时长溢出、硬件缺口、前置断链

* [ ] 交付说明：你（或 AI）附一份 "我改了哪些、没改哪些、哪些待你拍板"

### 6.3 可选：回传开源

你改出了漂亮的版本？欢迎回传（Issue / PR / 邮件），我们乐意署名收录，让更多老师受益 —— 这也是 courses-M0 开源协议（CC BY 4.0）鼓励的循环。详见《交付物使用指南》第六节。
